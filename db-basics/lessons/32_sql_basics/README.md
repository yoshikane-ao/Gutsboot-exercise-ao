演習1
【ファイル保存のつらい点(3つ)】
1. 同時更新がやりづらい。
2. 扱っていているデータが壊れやすい。
3. データの検索や変更がやりづらい。

【DBが解決しやすい点(3つ)】
1. 同時編集を行うことができる。
2. データの検索や変更が容易にできるようになる。
3. データが壊れづらくなる。



演習２
【RDBの強み(3つ)】
1. 構造が明確
2. 整合性が強い
3. SQLが強力

【NoSQLの強み(2つ)】
1. 柔軟なデータ構造
2. 大量データの処理・スケールに強い。

【使い分けのイメージ(1つ)】
<!-- 重複しそうなデータや、今後変更がありそうなデータをNoSQLに保存し、NoSQLに保存した際のIDなどの呼び出しをRDBで行う。 -->
整合性・関係性重視　→　RDB
大量データ・高速処理重視 → NoSQL


演習3
【用語カードを作る(必須)】
　 【用語】 ｜【説明】
1. テーブル ：表全体
2. カラム　 ：列（縦）
3. レコード ：行(横)
4. 主キー　 ：レコードを一意に識別するための列
5. 外部キー ：他のテーブルの主キーを参照する列
6. 正規化　 ：重複データを減らす、更新時の事故を減らす。

【家計簿】

テーブル2：stock（入出庫）
